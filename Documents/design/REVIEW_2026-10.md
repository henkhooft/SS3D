# Design review ledger — 2026-10

> Status: active

A record of the October 2026 grill that checked the design docs against what had shipped since July 2026. Each row is one conflict between a design doc, the implementation, a milestone or another design doc, with the owner's decision. This file is a review record, not a spec: the design docs themselves carry the decisions after the edit pass. Read it to learn **why** a design section changed in 2026-10.

**Ground rules settled before the review:**

- **Scope:** docs with shipped or in-progress code, or cited by a current milestone (MVP1, test-server, map-authoring, MVP2).
- **Code vs design:** where the code made a decision recorded in an effort or plan, the design adopts it by default. Every case was still put to the owner.
- **Feasibility:** docs a milestone cites are trimmed to a first pass that milestone can reach, and the rest moves to `§Out of scope for this pass`. Docs that no milestone up to MVP2 needs are set to `Status: deferred`.

## Combat, armor, health, stamina

| # | Docs | Conflict | Decision |
|---|---|---|---|
| Q5 | armor §1 | Environmental burn was meant to go through combat armor, but per-hit flat absorption cannot handle per-second exposure ticks (full immunity plus integrity drain). | Combat armor handles hits. Suits carry separate **environmental protection** (heat, cold, pressure) that scales exposure down. |
| Q6 | combat §2/§3, health §2/§7 | Combat called toxin and oxy per-limb; health says systemic. | Health wins: weapons deal per-limb brute and burn, toxin and oxy are systemic. |
| Q7 | stamina §2, armor §4, inventory §10 | Weight was cited as a stamina input that stamina §2 never defined. | Stamina §2 adds weight: **all carried weight** lowers both the cap and regen. |
| Q8 | combat §2 | "Click connects" vs the shipped windup that resolves the zone at the end and can miss. Timed blocking was fragile under server authority and latency. | Adopt the windup that resolves at the end; a miss still costs recovery. Timed blocking moves out of scope. |
| Q9 | combat §3 | "Braced" narrows the cone but no brace state exists. | Drop "braced" for this pass. |
| Q10, Q23 | combat | Knockdown, ammo, friendly fire and two-handed weapons were decided in code or milestones with no design. | New sections: stagger and knockdown (about 2–3 s, HUD alert); magazines with a swap action and the ammo count on examine (loose rounds out of scope); friendly fire always on, sides told apart by outfit and the examine name with no IFF overlays; two-handed weapons need a free off hand. |
| Q11 | health §2/§4/§5 | Severing needs the Disabled tier plus a sharp weapon; critical drains into cardiac arrest; the code keeps the mind in a severed head. | Adopt severing and the critical countdown. **Decapitation is death**, and the brain can be recovered later (the code deviates; parked). |
| Q12 | armor §2/§3 | No rule for layered pieces; the seal covered only oxy, not barotrauma. | The outermost piece absorbs and wears first; a breach punctures the outermost sealed piece; the seal blocks oxy debt and pressure damage to the lungs. |
| Q13 | stamina §4 | Weapon sway relied on aim IK, which was deferred. | Reticle bloom is the main exhaustion read; sway comes later with aim IK. |
| — | combat, health, armor | Stale text: hitscan still open, armor "out of scope", "seven-zone rig unchanged", organs "already exist". | Fixed. Transplants, cybernetics, limb reattachment and visible armor wear move out of scope. |

## Adopted from code by default

Shipped behaviour the design took over under the "code wins by default" rule, without a separate question. The owner confirmed this list, and the meaning given to the `Restricted` role (`admin-tools.md` §2), on 2026-10-31.

- **Lobby:** High/Medium/Low/Never priority chips instead of a drag-ranked list; latejoin uses the same chips; a character creator instead of name-only entry; a Server Info tab (MOTD, build, changes); preferences kept for the server session (`lobby.md` §2, §3, §6, §7).
- **Round config:** the admin picks Secret, Extended or a named mode directly; weighted pools become a later pass (`round-config.md` §1, §2, §7).
- **Examine:** hover tooltip, Shift for the detail panel, and a persistent Search view on characters, instead of hold-to-peek (`examine.md` §4).
- **Inventory:** plain drag between panels instead of the Tier 3 combine grammar; a locker's panel only while its door is open (`inventory-storage.md` §6).
- **Main HUD:** a machine's screen replaces the HUD instead of sitting on top of it (`main-hud.md` §4).
- **Admin tools:** round controls (start, hold, extend, cancel, end), MOTD and server-name editing, and the playtest wedge tools (`admin-tools.md` §5, §6).
- **Networking:** version-mismatch rejection, staying connected across rounds, and Retry/Quit on losing the server (`networking.md` §5, §6).
